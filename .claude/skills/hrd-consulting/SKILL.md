# HRD Consulting — 研修企画・設計・開発／営業／カスタマーサクセス

このスキルは、人材育成ビジネスのバリューチェーン全体（**売る → 設計する → 届ける → 定着させて次につなぐ**）を一気通貫で支援するためのもの。各アウトプットは単体で完結させず、前後の工程とつながっていることが品質の本質である。たとえば提案書の「目標」は、研修設計の学習目標、アセスメントの評価基準、CSの効果測定KPIと**同じ言葉・同じ指標**でつながっていなければならない。ここがずれると「研修は好評だったが、何が変わったか説明できない」という業界の典型的失敗に陥る。

## 1. 依頼を受けたら最初にやること

### 1-1. 領域を判定し、該当する参照ファイルを読む

| 依頼の中心 | 読むファイル |
|---|---|
| 研修の企画・カリキュラム・教材・進行表・ファシリテーターガイド | `references/training-design.md` |
| 評価基準表（ルーブリック）・事前／事後アンケート・効果測定・ROI | `references/assessment.md` |
| ヒアリングシート・トークスクリプト・提案書・提案メール・反論処理 | `references/sales.md` |
| 研修後の定着支援・ヘルススコア・QBR・継続／アップセル提案 | `references/customer-success.md` |
| 各アウトプットの構成テンプレート（スライド構成、Excelの列定義など） | `references/deliverables.md` |

複数領域にまたがる依頼（例：「商談準備から提案書まで」）では、該当ファイルをすべて読む。ファイルを作る依頼では `references/deliverables.md` のうち、作るアウトプットの節だけを読めばよい（目次から該当節に飛ぶ）。関係のない参照ファイルまで読むと時間がかかるだけで品質は上がらない。

### 1-2. 自社テンプレートを確認する

`assets/company/` に自社の企画書・提案書・フォーマット・独自フレームワークが置かれている場合は、**業界標準より自社資料を優先**する。自社の型に沿わない資料は、品質が高くても現場で使われないからである。フォルダが空なら、業界標準（このスキルの参照ファイル）に基づいて作成する。

### 1-3. 前提が足りない場合

最適な設計に不可欠な情報（対象者、人数、期間・時間、目的、予算感など）が欠けているときは、確認質問を**最大3つ**に絞って提示する。ただし、ユーザーが「まず叩き台を」と求めている、または合理的な仮定で進められる場合は、仮定を明示（「前提：受講者30名・1日研修と仮定」）して作成を進め、最後に「この前提が違えば修正します」と添える。止まりすぎるより、叩き台で議論を前に進めるほうが価値が高い。

## 2. 共通の思考プロセス

どの領域でも、次の順で考える。これは研修設計（ADDIEの分析→設計）、営業（SPINの状況→問題→示唆→解決）、CS（現状→ギャップ→打ち手）に共通する骨格である。

1. **経営・事業課題**：顧客企業は何を達成したいのか（売上、離職率、品質、DX推進など）
2. **業務上のギャップ**：その課題を生んでいる現場の行動は何か（何が「できていない」のか）
3. **原因の切り分け**：知識・スキル・意識の問題か、それとも仕組み・評価制度・上司の関与の問題か。**研修で解決できない原因**（制度や業務設計の問題）は正直に指摘する。研修万能論で提案すると、効果が出ずに信頼を失う
4. **到達目標**：研修後に「誰が・何を・どの水準で」できるようになるか（観察・測定できる行動で書く）
5. **打ち手と測定**：研修＋前後の仕掛け（事前課題、上司面談、職場実践、フォロー）と、レベル1〜4の測定方法

## 3. 品質基準（全アウトプット共通）

- **結論から書く**：企画書・提案書・メールとも、冒頭で「何を・なぜ・どうなるか」を示す
- **目標は行動動詞で**：「理解する」「意識する」ではなく「〜できる」「〜を実施している」と観察可能な形にする。理由：測定できない目標は評価も改善もできないから
- **一貫性**：提案書の目標＝カリキュラムの学習目標＝ルーブリックの評価項目＝アンケートの設問＝QBRのKPI、となるように用語と指標を揃える
- **事実と推測を分ける**：統計・市場データ・他社事例を使うときは、出典と時点を明記する。確認できない数値は作らず「（要確認）」と書く。推測や仮説には「（仮説）」と付ける。顧客に提出される資料で数値の誤りがあると、提案全体の信頼が崩れるため
- **受講者視点**：講義だけの時間が長く続かないようにし（目安は1区切り15〜20分以内）、演習・対話・振り返りを組み込む
- **そのまま使える完成度**：プレースホルダー（「〇〇」）は、顧客名など本当に未知の情報だけに限る。中身は具体的に書き切る

## 4. 出力形式の選び方

ファイル形式の指定がない場合は、次を標準とする。ファイルの作成手順そのものは、該当する形式のスキル（pptx / xlsx / docx、または利用可能ならドキュメント・スライドの成果物）に従う。

| アウトプット | 標準形式 | 理由 |
|---|---|---|
| 研修企画書・提案書・QBR資料 | スライド（pptx またはデッキ） | 顧客との説明・意思決定の場で使うため |
| カリキュラム・進行表・評価基準表・ヘルススコア | Excel（xlsx） | 時間計算・並べ替え・集計・再利用のため |
| 受講者テキスト・ワークシート・ファシリテーターガイド | Word（docx）またはドキュメント | 印刷・配布・書き込みのため |
| 事前・事後アンケート | Excel（設問一覧）＋必要に応じてフォーム化用の設問テキスト | Googleフォーム／Microsoft Forms等へ転記しやすくするため |
| ヒアリングシート・トークスクリプト・提案メール | ドキュメントまたは本文テキスト | 商談前にすぐ読める・コピーして送れるため |

ユーザーがチャットでの回答（叩き台・骨子）を求めている場合は、ファイルを作らずMarkdownで返してよい。

## 5. 仕上げのチェック

納品前に、次を自問する。

- 顧客の経営課題から、目標・内容・測定までが一本の線でつながっているか
- 目標と評価項目は観察・測定できる行動で書かれているか
- 時間配分の合計は、指定された研修時間と一致しているか（進行表は計算で確認する）
- 出典のない数値や、断定しすぎている表現はないか
- 研修だけでは解決できないリスク（上司の関与、制度、業務負荷）に触れているか
- 複数のファイルを作った場合、ファイル間で数字・時間・目標の文言が一致しているか（例：企画書のカリキュラム概要と進行表の時間配分、ルーブリックとアンケートの行動項目）。ずれていると、顧客は資料全体を信用しなくなる
- 効果測定の各レベルに「合格・目標の基準」（例：L2はルーブリック3点以上が80%）が書かれているか。基準のない測定は、結果が出ても良し悪しを判断できない
- 使う人がその資料を「使う場面」まで想定できているか（例：QBRなら当日の進行と想定問答、メールなら状況別の差し替え案）
