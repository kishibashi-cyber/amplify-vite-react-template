## 1. ADDIEの各フェーズで決めること

| フェーズ | 決めること | 主なアウトプット |
|---|---|---|
| Analysis（分析） | 経営課題・業務上のギャップ・対象者・制約条件 | ニーズ分析シート、研修企画書の「背景・課題」 |
| Design（設計） | 到達目標・学習目標・構成・手法・評価方法 | 研修企画書、カリキュラム |
| Development（開発） | 教材・演習・ケース・進行 | 受講者テキスト、ワークシート、スライド、ファシリテーターガイド、進行表 |
| Implementation（実施） | 運営・講師・事前課題・連絡 | 運営マニュアル、案内文 |
| Evaluation（評価） | レベル1〜4の測定、改善 | アンケート、ルーブリック、効果測定レポート（`assessment.md` 参照） |

ADDIEを一方向の滝のように進める必要はない。短期間で試作・改善を繰り返すSAM（Successive Approximation Model）的な進め方も有効で、特に新規テーマや顧客の合意形成が必要な場面では、早めに叩き台（研修の骨子）を見せて修正するほうが速い。

## 2. ニーズ分析（Analysis）

3つの層で分析する。

| 層 | 問い | 情報源 |
|---|---|---|
| 組織 | 事業戦略上、どんな人材・行動が必要か | 中期経営計画、人事方針、経営層インタビュー |
| 業務 | その職務で成果を出すには何ができる必要があるか | 職務記述、ハイパフォーマー分析、上司ヒアリング |
| 個人 | 対象者の現状レベルと、目標とのギャップは | 事前アセスメント、評価データ、サーベイ |

**研修で解決できるか**の判定：ギャップの原因が「知らない・やり方がわからない」なら研修が有効。「わかっているがやらない」なら、動機・評価・上司の関与・業務環境の問題であることが多く、研修単体ではなく、上司の巻き込みや制度とセットで提案する。

## 3. 学習目標の書き方（Design）

**ABCD形式**で書く：Audience（誰が）、Behavior（何を：行動動詞）、Condition（どんな条件で）、Degree（どの水準で）。

- 悪い例：「1on1の重要性を理解する」
- 良い例：「新任管理職が（A）、部下との1on1で（C）、傾聴・質問・承認の3技法を使い、部下が自ら次の行動を決める対話を（B）、ロールプレイの評価基準で3点以上の水準で実施できる（D）」

**ブルームの分類（改訂版）**の段階（記憶→理解→応用→分析→評価→創造）を意識し、研修の目的に合った動詞を選ぶ。管理職研修・実務研修では「応用」以上を目標にするのが基本。

**到達目標の階層**：
- 研修目的（ビジネスゴール）：例「新任管理職の部下の離職率を下げる」→ レベル4
- 行動目標（職場で何をするか）：例「月1回以上、部下と30分の1on1を実施する」→ レベル3
- 学習目標（研修終了時に何ができるか）：例「ロールプレイで3技法を使える」→ レベル2

## 4. カリキュラム設計の原則

- **構成の流れ**：導入（目的・期待の共有）→ 気づき（自己診断・ケース）→ 知識のインプット → 演習・実践 → 振り返り → 職場での実践計画
- **時間配分の目安**：講義（インプット）は全体の30〜40%以内、演習・対話・振り返りを60%以上にする。1回の講義は15〜20分以内で区切る。大人の学習（アンドラゴジー）は、経験に結びつけ、すぐ使えると実感できるときに最も定着するため
- **休憩**：60〜90分ごとに10分程度。昼食は60分
- **1日研修の典型**：9:30〜17:30（実質6時間＝休憩・昼食を除く）。半日は3〜3.5時間
- **70:20:10の考え方**：研修（10）だけで終わらせず、上司からのフィードバック（20）や職場での実践（70）につながる仕掛けを設計に含める。例：事前の上司面談、研修後の実践課題、1か月後のフォロー研修
- **分割型（反転学習）**：知識インプットはeラーニングや事前課題に回し、集合研修は演習に集中させると効果が高い

### 研修手法の選び方

| 目的 | 適した手法 |
|---|---|
| 知識の習得 | 講義、eラーニング、事前の読み物、クイズ |
| スキルの習得 | ロールプレイ、ケーススタディ、デモ→実践→フィードバック |
| 意識・態度の変容 | 自己診断、ディスカッション、体験型ワーク、他者からのフィードバック |
| 職場での実践 | アクションプラン、上司との面談、実践レポート、フォロー研修 |

## 5. 教材開発（Development）

### 受講者用テキスト
- 章立ては進行表のパートと一致させる（受講者が「今どこか」わかるようにする）
- 各章：ねらい → 要点（図解・フレームワーク）→ 事例 → 演習への指示 → まとめ
- 書き込み欄を設け、テキストが研修後も職場で使える「手引き」になるようにする

### ワークシート
- 1シート1演習。冒頭に「目的」「所要時間」「進め方（手順を番号付きで）」を書く
- 記入欄は具体的な問いにする（「気づいたこと」より「あなたのチームで最も時間を取られている業務を3つ挙げてください」）
- 記入例を付けると質が揃う

### ファシリテーターガイド（講師用手引き）
- パートごとに：ねらい／時間／進め方（話す内容の要点・問いかけ・板書）／演習の指示文／想定される反応と対応／時間が押したときの短縮案
- 講師が変わっても同じ品質で実施できること（再現性）が目的。社内講師に展開する場合は特に重要

### 研修進行表（タイムテーブル）
- 列：開始時刻／終了時刻／所要時間（分）／パート名／ねらい／内容／手法／使用教材／講師の動き／受講者の動き
- 所要時間は数式で計算し、合計が研修時間と一致することを必ず確認する

## 6. 実施と評価への接続

設計段階で評価方法を決めておく（後付けにしない）。各学習目標に対して「どのレベルで・何を使って・いつ測るか」を設計表に入れる。詳細は `assessment.md`。
